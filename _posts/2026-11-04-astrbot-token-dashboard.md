## 起因

前阵子给群里的 bot 换了个模型，跑了两天，账单比预想的难看。想知道 token 到底花在哪儿了，翻了一圈发现 AstrBot 其实把每次调用的数据都老老实实记在 `provider_stats` 表里了，只是没有地方能看。

于是就有了这个插件：[astrbot_plugin_token_dashboard](https://github.com/Heluowen/astrbot_plugin_token_dashboard)。

## 思路很简单：只读

没有去碰请求链路，也没有往 prompt 里塞任何东西，就是**只读** AstrBot 自己维护的那张表，然后在 WebUI 插件页里聚合成一个看板。好处是不会影响对话质量，也不会把前缀缓存搞失效——这点在下面会讲到，它其实很重要。

页面里现在有几块：

- **总览**：请求数、输入 token（命中 / 未命中）、缓存命中率、输出 token、估算花费
- **时间序列**：每段输入 token 的堆叠柱状图，绿色是命中、红色是未命中，再叠一条命中率折线
- **按会话拆分**：每个群 / 每个私聊各自的请求数、输入量、命中率和花费
- **最近请求**：一条一条列出来，谁在什么时候花了多少
- **分时段计费**：每条请求按它**发生那一刻**的单价算钱，而不是一律按一个价

## 一个意外收获：命中率就是钱

以前我一直以为「缓存命中」是个性能指标，做完这个看板才发现它首先是个**价格**指标。

配置里的参考单价是这样的：输入 · 缓存未命中是 `2.0` 元/百万 token，命中是 `0.04`；输出是 `8.0`。也就是说，同样一段输入，命中与否差 **50 倍**。

反过来讲：如果你每天定时去改系统提示词、换人格、改工具描述，每个改动都会让缓存前缀失效，第二天全量重新计费。所以「少折腾 prompt」不只是工程洁癖，是实打实省钱的优化。

这条经验对做 bot 的人来说可能比看板本身还值。

## 聊天里直接看

不想开网页的时候，在聊天里发命令就行：

```
/token        # 近 24 小时
/token 168    # 近 7 天
```

返回一张紧凑的文本账单：请求数、命中率、输入输出、花费。

## 踩的两个坑

**一是时区。** 计费时段只按北京时间算，跟服务器本地时间没关系，所以整个插件里时间是统一的。高峰是三档里的两段：周一到周五（不含法定节假日）的 `09:00-12:00` 和 `14:00-18:00`，其余时间按空闲价——包括周末、晚上和午休。

**二是节假日。** 这个没法内置，每年由国务院公布，所以插件留了个 `holidays` 字段让你手填，支持单日和区间：

```json
["2026-01-01", "2026-02-16..2026-02-22", "2026-10-01..2026-10-07"]
```

留空也不会坏，只是节假日当天的工作时段会按高峰价算，估算会偏高一点。

另外会话 ID 是一串数字，看不太懂是谁，配置里可以用 `session_labels` 映射成名字：

```json
{"2132379270": "潮汕牛肉火锅", "336611682": "私聊-老友"}
```

## 安装

两种方式都行。丢进插件目录然后重启：

```bash
cd <AstrBot 数据目录>/plugins
git clone https://github.com/Heluowen/astrbot_plugin_token_dashboard.git
```

或者在 AstrBot WebUI 的插件页用「从 URL 安装」。注意目录名得是 `astrbot_plugin_token_dashboard`，跟仓库名一致，不然加载不到。

装完打开 WebUI → 插件页 → 「Token 用量看板」就能看到数据了，页面默认 60 秒自动刷新，可以在配置里改。

## 最后

数据来源是 AstrBot 自己的表，插件只做聚合展示，花费是按 token 数和配置单价**估算**的，不含任何平台优惠，所以跟真实账单对不上是正常的——参考单价也请按自己的实际账单核对一遍再调。

有问题或者想看什么指标，欢迎在 [仓库](https://github.com/Heluowen/astrbot_plugin_token_dashboard) 提 issue。
